# 메뉴 항목 번호 정리 (2026-10-09)

메뉴 항목을 취소하면 남은 항목에 1부터 연속 번호를 다시 부여합니다.

- `1, 2, 3, 4, 5`에서 3번 취소 → `1, 2, 3, 4`.
- 다음 발화의 “3번”은 새 3번(원래 4번)을 가리킵니다.
- “3번과 4번 취소”는 두 항목을 모두 기존 번호로 찾은 뒤 한 번만 재번호를 부여합니다.
- 새 메뉴는 남은 메뉴의 마지막 번호 다음에 추가됩니다.
- 수량 감소로 여러 항목이 없어지는 경우, 전부 취소 후 다시 추가하는 경우도 동일합니다.
- 옵션 선택 대기와 세트 그룹, 최근 선택한 항목도 새 번호로 변환합니다.

고객 접수 누적번호 `order_no`와 맥오더 예약번호는 바꾸지 않았습니다.
PUB 기능과 메뉴 요약·총액 계산도 그대로 포함되어 있습니다.
맥오더 봉투는 누적번호로 찾고, 고객 발화에는 맥오더 예약번호를 사용합니다.
봉투에 두 번호를 표기한다면 인식 노드가 누적번호를 `order_number`로 보내야 합니다.

## 적용

직전 주문 PUB 버전을 이미 적용했다면 실행 코드 변경은 `llm/order_runtime_final.py` 한 파일입니다.
기존 파일을 백업하고 이번 ZIP의 같은 파일로 교체한 뒤 주문 앱을 다시 실행하세요.
새 고객을 받기 전에 적용하고, 진행 중인 주문이 있을 때는 앱을 종료하지 마세요.
기존 `runtime_data/`의 접수 순번/발행 이력은 그대로 유지합니다.
이 수정만 적용할 때 vLLM 및 IO 런치는 다시 실행할 필요가 없습니다.

PUB 버전도 아직 적용하지 않았다면 이번 전체 ZIP에 PUB 기능과 번호 정리가 모두 들어 있습니다.
`ROS_ORDER_PUB_KO.md`에 따라 새 앱과 새 IO 런치를 함께 사용하세요.

## 검증

실사용용: 항목 번호·개별 메뉴·modifier·PUB 테스트 **322개 통과**.
GitHub용 코드에 외부 테스트 적용: 번호·modifier·PUB **302개 통과**.
공통 실행 파일은 양쪽이 바이트 단위로 일치합니다. GitHub용에는 테스트 파일을 포함하지 않습니다.
기존 오프라인 회귀 스크립트 10개도 통과했습니다.
기존 잡음 입력 차단 테스트 실패와 실제 ROS/로봇 실행 범위는 이전 검토 보고서를 참고하세요.

```bash
cd llm
source ~/drive_thru_venv/bin/activate
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q test_line_renumber.py test_individual_items.py test_modifier_selection.py test_main_order_publish.py
```

이전 `test_ids_not_reused`는 항목 번호가 계속 증가한다는 과거 정책의 테스트였습니다.
새 요구사항에 맞춰 남은 항목 다음 번호로 추가되는지 검증하도록 바꿨습니다.
나머지 기존 테스트의 검증 조건은 그대로 유지했습니다.
